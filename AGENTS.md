# Baron Boomhausen

Baron Boomhausen — лёгкая HTML5-игра для браузера и публикации на itch.io. Исходный геймдизайн описан в [GDD](docs/baron_boomhausen_gdd.md). Соблюдай решения с пометкой «Зафиксировано». Параметры и механики с пометкой «Предложение» проверяй на прототипе. Очерёдность реализации бери из раздела о версии для джема.

## Стек и вес игры

- Пиши на TypeScript в строгом режиме. Используй Vite для локальной разработки и статической сборки, Canvas 2D для игрового мира, HTML и CSS для кнопок, панелей и меню.
- Начинай со стандартных браузерных API. Добавляй зависимости только под конкретную задачу, если они заметно упрощают реализацию и их вклад в вес сборки оправдан. Игровой движок, UI-фреймворк, физическая библиотека и сервер для текущего объёма проекта не нужны.
- Держи первый запуск лёгким. Используй простую графику, компактные изображения и короткие звуки. Подключай тяжёлые ресурсы по мере необходимости. Избегай внешних шрифтов, CDN и сетевых запросов для основного игрового цикла.
- При добавлении ассетов или зависимостей проверяй общий размер `dist/` и объём ресурсов, загружаемых до первого выстрела.
- Сборка должна работать в iframe itch.io с относительными путями к ресурсам. Для публикации запускай `build-release.cmd`. Он собирает `dist-release/` и упаковывает его содержимое в `baron-boomhausen.zip` с `index.html` в корне. Отладка и страница проверки звука доступны в обычной сборке и исключены из релиза.

## Визуальный стиль

- Референс — [плоская геометрия](docs/art-concepts/09-geometric-flat.png). Используй крупные силуэты, простые кривые и сочные однотонные заливки. Основная палитра — голубой, коралловый, лимонный, фиолетовый, мятный и кремовый.
- Держи Барона, награды и препятствия контрастными на фоне. Игровые спрайты храни в [игровом SVG-атласе](src/assets/game-atlas.svg), графику интерфейса — в [UI-атласе](src/assets/ui-atlas.svg). При изменении прямоугольников спрайтов обновляй `atlas-frames.json`. Подписи и значения в интерфейсе выводи текстом в HTML.
- Язык игры — английский (`en`). Все видимые тексты, подсказки и доступные подписи пиши на английском.

## Игровые правила

- Основной цикл — расставить барона и заряды в одной стартовой зоне, нажать **BOOM!**, посмотреть полёт и поправить расстановку по пунктиру последней попытки.
- Все обычные заряды срабатывают одновременно при запуске. Игрок начинает с трёх базовых зарядов. Открытый запас восстанавливается на каждую попытку, а лимит в 10 действует отдельно для каждого типа взрывчатки.
- Ящики увеличивают постоянный запас соответствующего типа, чертежи навсегда открывают установки. Экономика, жизни и штрафы за повторный запуск не входят в проект.
- Мир непрерывный. В базовой версии предусмотрены обзор карты, миникарта, возврат к барону, рекорды высоты и дальности и достижимая Луна. После попадания на Луну можно продолжать игру.
- Силы и радиусы зарядов, гравитацию, координаты и другие параметры баланса держи в явной конфигурации. Проверяй, что три стартовых заряда позволяют достать хотя бы до одного ближайшего шара, а открываемый набор даёт воспроизводимый путь к Луне.

## Симуляция и сохранения

- Отделяй расчёт полёта от отрисовки, камеры и ввода. Симуляция идёт фиксированным шагом, отрисовка работает через `requestAnimationFrame`. Время выстрела задаёт начальную фазу уток, облаков и шариков с наградами. При одинаковой фазе частота кадров и визуальные эффекты не должны менять попадания, а траектория барона не зависит от времени подготовки.
- Одинаковая расстановка, состояние мира и действия на тех же тиках дают одинаковые траекторию и события. Сбрасывай время попытки при старте, держи порядок обработки событий стабильным и проверяй столкновения вдоль пройденного за шаг отрезка, чтобы быстрый барон не пролетал сквозь цели.
- Храни точки последнего полёта в мировых координатах. Сохраняй прогресс, рекорды, достижение Луны и последнюю траекторию через версионированное локальное сохранение. Пустое или повреждённое сохранение не должно мешать запуску игры.
- Используй Pointer Events для перетаскивания мышью и касанием. Переводи координаты указателя через преобразование камеры и ограничивай размещение стартовой зоной.

## Разработка и проверка

- Сохраняй небольшие изменения и переиспользуй существующий код. Избегай абстракций для механик, которые ещё не понадобились.
- При настройке проекта добавь `npm run dev` для разработки, `npm run check` для проверки типов и `npm run build` для сборки в `dist/`. После изменений кода запускай проверку типов и сборку.
- На Windows запускай `run-dev.cmd`, чтобы открыть Vite с `?debug=1`. `build-dev.cmd` собирает `dist/` с отладочной панелью по умолчанию и страницей `sounds.html`.
- Для изменений игрового цикла проверь путь от расстановки до повторной попытки в браузере. При изменении физики сравни траектории и события двух запусков с одинаковыми входными данными. При изменении прогресса проверь восстановление после перезагрузки страницы.
